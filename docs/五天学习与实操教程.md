## 先理解你到底在做什么

客户说 `I lost my card`，程序要输出 `lost_or_stolen_card`，再决定是否有足够把握自动送到对应服务队列。

```text
英文问题
  → tokenizer：把句子转成 token ID
  → 冻结 MiniLM：每个 token 变成 384 维向量
  → 带 attention mask 的平均池化 + L2 归一化
  → 句子向量 [384]
  → 自己训练的 PyTorch 分类头
  → 77 个 logits
  → 温度缩放与 softmax
  → Top-3 意图 + 置信度 + 自动/人工分流
```

你训练的是最后的分类头。MiniLM 的参数保持冻结。这个系统不生成回答，也没有实际连接人工客服。

### 2. Python 最少需要会这六件事

在 Python 解释器中逐行执行，再自己改数字：

```python
# 变量、列表与字典
labels = ["card_arrival", "lost_or_stolen_card"]
row = {"text": "I lost my card", "label": 1}
print(row["text"], labels[row["label"]])

# 循环、条件与函数
def route(confidence, threshold=0.6):
    if confidence >= threshold:
        return "auto"
    return "human"

for value in [0.3, 0.7, 0.95]:
    print(value, route(value))

# 列表推导式：对每个元素做同样的事
values = [0.3, 0.7, 0.95]
accepted = [value for value in values if value >= 0.6]
print(accepted)
```

函数用参数接收输入，通过 `return` 给出结果；类把状态和函数组织在一起。`IntentHead` 是一个类，实例里保存训练参数；`IntentService` 保存已加载的编码器和分类头，避免每次请求都重新读磁盘。

### 3. 张量与维度

```python
import torch
x = torch.randn(8, 384)
weights = torch.randn(384, 77)
logits = x @ weights
print(x.shape, logits.shape)  # [8, 384] → [8, 77]
```

张量可以先理解成支持自动求导和 GPU 运算的多维数组。`8` 是 batch 中句子数，`384` 是每句的特征数，`77` 是意图数。矩阵乘法要求中间维度一致。

数学上，线性分类器计算 `z = xW + b`。MLP 在中间再加入隐藏层：`z = ReLU(xW1+b1)W2+b2`。ReLU 为 `max(0,a)`，使模型不再是单次线性映射。

### 4. 亲手运行最小训练程序

```powershell
.\.venv\Scripts\python.exe lesson_torch.py
```

打开 `lesson_torch.py`，圈出下面四步：

```python
optimizer.zero_grad(set_to_none=True)  # 清掉上一次的梯度
loss.backward()                       # 按链式法则反向传播
optimizer.step()                      # 根据梯度更新参数
```

在它们之前先做前向计算 `logits = model(x)` 和 `loss = cross_entropy(logits, y)`。这里为了展示自动求导使用同一份玩具训练数据，没有正式测试集；100% 的玩具训练准确率不能写成项目效果。

交叉熵对正确类别 `y` 的单个样本损失是 `-log softmax(z)[y]`。正确类概率从 0.1 提升到 0.8，损失就从约 2.303 降到 0.223。

`cross_entropy` 接受原始 logits，内部已有 log-softmax。不要先对 logits 做 softmax 再传给这个损失函数。标签是 `torch.long` 的类别编号，不是句子字符串。

### 今日练习与答案

1. 把 batch=8 改成 16，输出是什么形状？答案：`[16,77]`。
2. 去掉 `zero_grad` 会怎样？答案：PyTorch 默认累加梯度，后续更新会混入前几步的梯度。
3. 为什么演示需要 `model.eval()`？答案：关闭 Dropout 的训练随机性；它和关闭求导是不同的事情。
4. `torch.inference_mode()` 做什么？答案：关闭推理时不需要的求导记录，减少开销，不负责切换 Dropout。

### 2. 解释四个分区

| 分区 | 大小 | 可以做什么 |
|---|---:|---|
| train | 6,962 | 拟合 TF-IDF 词表、IDF 和分类头参数 |
| selection | 1,492 | 比较结构、选择 C 和早停轮数 |
| calibration | 1,492 | 拟合温度、选择自动分流阈值 |
| test | 3,080 | 所有决定固定后报告最终表现 |

分层抽样让各类比例尽可能相近。四个分区之间不存在规范化文本重叠。`test` 内部仍有 4 条重复，未修改官方测试。

为什么不只分 train/test？你如果不停看 test 改学习率，test 就被用来选模型，最终结果会偏乐观。校准也是拟合过程，因此也要有数据隔离。去污染使用测试输入这一点在本项目协议中公开，不假称完全从未查看测试输入。

### 3. 理解传统基线

TF-IDF：经常出现在某句话、但不是到处都出现的词，更可能区分这句话的意思。scikit-learn 的平滑 IDF 形式为 `log((1+n)/(1+df))+1`；本项目对 TF 使用 `1+log(tf)`，最后做向量归一化。`ngram_range=(1,2)` 同时考虑单词与相邻词组，`min_df=2` 排除只出现一次的词项。

Logistic Regression 将稀疏词特征映射成 77 类分数，再计算分类概率。C 控制正则化强度的倒数，C 越大通常约束越弱，不代表一定更好。本项目只在选择集比较 C=1 与 C=4。

在 `run_experiment.py` 找到：

```python
train_tfidf = vectorizer.fit_transform(train_texts)
select_tfidf = vectorizer.transform(selection_texts)
```

`fit` 学词表和 IDF，`transform` 只使用已经学好的映射。不能把四个分区合起来 `fit`。

### 2. 按实际代码跟踪维度

假设 batch 为 64，当前最大片长为 L≤128：

```text
input_ids:       [64, L]       整数，词片编号
attention_mask:  [64, L]       真实 token=1，padding=0
hidden states:   [64, L, 384]  编码器给每个 token 的向量
pooled:          [64, 384]     只平均真实 token
hidden layer:    [64, 128]
logits:          [64, 77]
targets:         [64]          0..76 的整数标签
loss:            []            标量
```

`mean_pool` 计算：`e = sum(mask_i * h_i) / max(sum(mask_i), 1)`，之后用 `e/||e||₂` 归一化。不能把 padding 一起平均，否则同一句话会因为和更长的句子组成 batch 而改变特征。

MiniLM 使用 Transformer 的注意力结构，帮助词向量结合上下文。入门先掌握调用边界和输出形状；这个五天版本不要求你从零实现多头注意力。

### 3. 冻结编码器的含义

在 `encoder.py` 查看：

```python
self.model.eval()
self.model.requires_grad_(False)
```

再看 `model.py`，传给 optimizer 的只有 `IntentHead.parameters()`。因为编码器不更新，可以先编码并缓存，分类头每一轮训练都不用重新跑编码器。这是冻结特征迁移学习。若更新 Transformer 参数，就是另一种更昂贵的端到端微调；不能把本项目说成做了 LoRA 或大模型微调。

### 4. 看懂真正的训练设置

- `DataLoader` 每次给出一个随机打乱的 batch，降低单条更新的噪声并利用矩阵计算。
- AdamW 的学习率为 0.003，weight decay=0.001；前者控制更新步长，后者约束权重规模。
- 隐藏层候选为 0（线性）与 128（MLP），选择集最终选中 128。
- Dropout=0.15：训练时随机屏蔽部分隐藏单元，推理时关闭。
- 每轮在选择集算 Macro F1，连续 8 轮没有改善则停止，并恢复最好的一轮参数；不是保留最后一轮。
- 种子 42/43/44 展示初始化和打乱产生的波动；同种子跨硬件、库版本也不一定完全一致。

## Day 4：把统计优势体现在概率评估上

### 1. 分类指标

Accuracy = 正确条数 / 总条数。Top-3 accuracy 看正确标签是否出现在前三个候选中。

对某个意图：`Precision = TP/(TP+FP)`，`Recall = TP/(TP+FN)`，`F1 = 2PR/(P+R)`。Macro F1 是先算各类别 F1 再简单平均，避免大类完全主导结果；它不是把全部类别的 precision 和 recall 先平均再取调和平均。

在 `reports/test_predictions.csv` 手工统计一小段数据，随后用 Python 复算完整 accuracy：

```python
import csv
rows = list(csv.DictReader(open("reports/test_predictions.csv", encoding="utf-8")))
accuracy = sum(r["true_intent"] == r["neural_intent"] for r in rows) / len(rows)
print(accuracy)  # 约 0.91948，对应固定部署 seed 42
```

### 2. 置信度并非正确率

模型说 0.9，是 softmax 输出，不代表它对当前个例有可证明的 90% 正确率。校准关心：一组预测置信度相近的样本，其实际正确比例是否也相近。

温度缩放：`p_k = exp(z_k/T) / sum_j exp(z_j/T)`。T>1 通常让分布更平，T<1 更尖。只要 T>0，类别排序不变，因此 Top-1 accuracy 不变。本项目在 calibration 上最小化 NLL 来拟合 T，不用 test。

NLL 是平均 `-log(p_true)`；错误又自信的预测会受到更大惩罚。ECE 把置信度分箱，按每箱样本占比加权 `|实际正确率-平均置信度|`。ECE 与分箱选择有关，本项目指标使用 15 箱，图为了阅读使用 10 箱，均明确注明。

本次额外演示发现：`I need help with my account.` 会被模型以约91.5%的置信度判为`terminate_account`。句子并未说明要关闭账户，这是一个具体的高置信度失败案例。`Can you help me?` 则置信度约11.6%，会转人工。两者说明模糊输入不一定都低置信度；阈值机制无法解决所有未知或不完整请求。这里的合成例子用于演示局限，没有人工真值标签，不计入BANKING77测试指标。

### 3. 人工分流的取舍

规则为 `max_probability >= threshold` 自动分流，其余转人工。

`coverage = 自动条数/总条数`，`accepted_accuracy = 自动且正确条数/自动条数`。

提高阈值通常会减少自动处理的请求，并提高剩余请求的平均质量，但有限样本上不保证严格单调。把所有问题都转人工能避免自动误判，却没有自动化收益；把所有问题都自动处理则会接受更多错误。

本项目在 calibration 上，从预先给定的阈值中选覆盖率最大且经验准确率至少 95%、自动接收至少 50 条的阈值。若不存在，就设置大于 1 的阈值，让全部转人工。这个规则不会证明未来准确率一定 ≥95%。

固定 seed42：测试接收 2,841/3,080 条，覆盖率92.24%，其中准确率95.56%，Wilson95%区间约94.74%–96.26%。区间下界仍低于95%，所以不能写成“保证95%以上准确率”。

### 4. 两种不确定性别混为一谈

三种子标准差：固定测试数据，换训练初始化和样本顺序，观察训练波动。

成对 bootstrap：固定训练好的两个模型，重采样同一批测试请求，观察它们准确率差的波动。每次抽样必须对两个模型使用相同的请求索引，否则丢失配对信息。项目用2,000次查询级重采样；原测试内部有少量重复，独立查询假设只是近似。

这里区间衡量的是给定已训练模型、给定数据分布的经验不确定性，不能推断客服成本或线上转化的因果变化。
